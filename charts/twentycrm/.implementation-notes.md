# Twenty CRM Helm Chart - Implementation Notes

## Overview

This helm chart was created by analyzing:
1. The AMecea community helm chart for Twenty CRM
2. The official Twenty k8s manifests from the Twenty repository
3. The listmonk helm chart structure as the baseline pattern

## Key Improvements Over AMecea Chart

### 1. **StatefulSet for PostgreSQL**
- **AMecea**: Uses Deployment for PostgreSQL
- **Our Implementation**: Uses StatefulSet with volumeClaimTemplates (follows listmonk pattern)
- **Benefit**: Proper data persistence guarantees for database workloads

### 2. **Headless Service for PostgreSQL**
- **AMecea**: Regular ClusterIP service
- **Our Implementation**: Headless service (clusterIP: None) for StatefulSet
- **Benefit**: Proper StatefulSet network identity management

### 3. **Init Containers for Database Readiness**
- **AMecea**: Direct startup
- **Our Implementation**: wait-for-postgres init container on server and worker
- **Benefit**: Ensures database is ready before application starts, preventing startup failures

### 4. **Session Affinity Configuration**
- **AMecea**: Basic service configuration
- **Our Implementation**: ClientIP session affinity with 3-hour timeout
- **Benefit**: Matches official Twenty k8s manifest requirements for sticky sessions

### 5. **Comprehensive Secret Management**
- **AMecea**: Basic secrets
- **Our Implementation**: Support for existingSecret pattern on all components
- **Benefit**: Better integration with existing secret management solutions (Vault, Sealed Secrets, etc.)

### 6. **Official Image References**
- **AMecea**: Generic postgres image
- **Our Implementation**: Uses `twentycrm/twenty-postgres-spilo:latest` (official Spilo-based PostgreSQL)
- **Benefit**: Matches official deployment with HA-ready PostgreSQL

### 7. **Resource Specifications**
- **AMecea**: Basic or missing resource specs
- **Our Implementation**: Comprehensive requests/limits for all components with sensible defaults
- **Benefit**: Better cluster resource management and QoS

### 8. **Storage Configuration**
- **AMecea**: Basic PVC support
- **Our Implementation**:
  - Server storage PVC (application data)
  - Docker data PVC (docker-specific storage)
  - PostgreSQL volumeClaimTemplates in StatefulSet
- **Benefit**: Matches official k8s manifest storage architecture

### 9. **Helper Templates**
- **Our Implementation**: Clean helper functions for:
  - PostgreSQL host determination (internal vs external)
  - Redis URL generation
  - PostgreSQL connection string
  - Standard label management
- **Benefit**: DRY principle, easier maintenance

### 10. **Health Probes**
- **AMecea**: May be missing or basic
- **Our Implementation**: Configurable readiness and liveness probes with sensible defaults
- **Benefit**: Better pod lifecycle management and self-healing

## Architecture

```
┌─────────────────────────────────────────────────┐
│                   Ingress                       │
│         (crm.example.com -> server:3000)       │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│              Server Deployment                  │
│         (twentycrm/twenty:latest)              │
│    - GraphQL API, Web UI, Migrations          │
│    - Mounts: server-storage, docker-data       │
└─────────────────────────────────────────────────┘
                        ↓
┌──────────────────┬──────────────────┬───────────┐
│                  │                  │           │
│  PostgreSQL      │   Redis          │  Worker   │
│  StatefulSet     │   Deployment     │  Deploy   │
│  (Spilo)         │   (Stack Server) │  (yarn)   │
│  - Port: 5432    │   - Port: 6379   │  - Jobs   │
│  - VolumeClaimT  │   - No persist   │  - Queue  │
└──────────────────┴──────────────────┴───────────┘
```

## Component Breakdown

### Server
- **Image**: `twentycrm/twenty:latest`
- **Port**: 3000 (HTTP)
- **Purpose**: Main application server (GraphQL API, web interface)
- **Features**:
  - Database migration runner (configurable)
  - Init containers for DB readiness
  - Health probes (readiness/liveness)
  - Two PVCs for storage
  - Session affinity service

### Worker
- **Image**: `twentycrm/twenty:latest`
- **Command**: `yarn worker:prod`
- **Purpose**: Background job processing
- **Features**:
  - Same environment as server (shared config)
  - Migrations disabled (handled by server)
  - Init container for DB readiness
  - Higher memory allocation (1-2GB)

### PostgreSQL
- **Image**: `twentycrm/twenty-postgres-spilo:latest`
- **Type**: StatefulSet with volumeClaimTemplates
- **Purpose**: Primary data store
- **Features**:
  - Spilo-based (Patroni + PostgreSQL for HA readiness)
  - Headless service for StatefulSet
  - Separate superuser and application user
  - Session affinity for connections
  - Configurable storage size and class

### Redis
- **Image**: `redis/redis-stack-server:latest`
- **Purpose**: Caching and message queue
- **Features**:
  - Noeviction maxmemory policy
  - No persistent storage (stateless)
  - Rolling update strategy

## Configuration Highlights

### Environment Variables (Server & Worker)
- `PORT`: Application port (3000)
- `SERVER_URL`: External URL for CORS/webhooks
- `PG_DATABASE_URL`: PostgreSQL connection string
- `REDIS_URL`: Redis connection URL
- `ACCESS_TOKEN_SECRET`, `LOGIN_TOKEN_SECRET`, `REFRESH_TOKEN_SECRET`: JWT secrets
- `STORAGE_TYPE`: "local" (using PVC)
- `RUN_DATABASE_MIGRATIONS`: "true" on server, "false" on worker

### Storage Mounts
- **Server**:
  - `/app/packages/twenty-server/.local-storage` → server-storage PVC (10Gi)
  - `/app/docker-data` → docker-data PVC (10Gi)
- **PostgreSQL**:
  - `/home/postgres/pgdata` → volumeClaimTemplate (10Gi)

### Secrets
1. **Tokens Secret** (`<release>-tokens`):
   - accessToken
   - loginToken
   - refreshToken

2. **PostgreSQL Secret** (`<release>-postgres-secret`):
   - postgres-password (application user)
   - postgres-superuser-password (admin user)

## Differences from Official Twenty K8s Manifests

### What We Added (from listmonk pattern):
1. StatefulSet for PostgreSQL (vs Deployment in official)
2. Init containers for database readiness checks
3. Helm templating with values.yaml configuration
4. Helper functions for dynamic configuration
5. Conditional deployment (can use external DB/Redis)
6. existingSecret pattern for better secret management
7. Common annotations and labels support
8. Configurable storage classes

### What Matches Official Manifests:
1. Spilo PostgreSQL image
2. Redis stack server image
3. Session affinity with 3-hour timeout
4. Environment variable structure
5. Storage mount points
6. Token-based authentication approach
7. Resource allocation patterns

## Usage Examples

### Quick Start
```bash
helm install my-crm ./charts/twentycrm
```

### Production Deployment
```bash
helm install my-crm ./charts/twentycrm -f - <<EOF
ingress:
  enabled: true
  className: nginx
  host: crm.mycompany.com
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  tls:
    - secretName: twentycrm-tls
      hosts:
        - crm.mycompany.com

server:
  serverUrl: https://crm.mycompany.com
  replicas: 2
  storage:
    storageClassName: fast-ssd

secrets:
  accessToken: "$(openssl rand -base64 32)"
  loginToken: "$(openssl rand -base64 32)"
  refreshToken: "$(openssl rand -base64 32)"

postgres:
  password: "$(openssl rand -base64 32)"
  superuserPassword: "$(openssl rand -base64 32)"
  storage:
    size: 50Gi
    storageClassName: fast-ssd
EOF
```

### Using External Database
```bash
helm install my-crm ./charts/twentycrm --set postgres.enabled=false \
  --set postgres.hostname=my-postgres.rds.amazonaws.com \
  --set postgres.existingSecret=my-db-secret
```

## Testing

Before deploying to production:

1. **Dry run to validate templates**:
   ```bash
   helm install my-crm ./charts/twentycrm --dry-run --debug
   ```

2. **Template validation**:
   ```bash
   helm template my-crm ./charts/twentycrm | kubectl apply --dry-run=client -f -
   ```

3. **Lint the chart**:
   ```bash
   helm lint ./charts/twentycrm
   ```
